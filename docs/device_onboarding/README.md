# 交换机自动化上线 — 整体框架设计

## 文档信息

- 状态：草案，逐模块细化中
- 范围：IDC 新建/扩容场景下，接入层 rsw、核心 csw、云互联 cbs、带外 oob 交换机从上架到入网的自动化
- 不含：服务器侧配置、防火墙策略、无线 AC/AP（已有 function_wifi）

## 一、目标

把"上架 → 开机 → 可运营"这段人工过程收敛成三件可管理的资产：**软件版本**、**配置基线**、**业务架构模板**。现场只需确认接线和序列号，其余由系统推导、生成、下发、校验。

验收标准：

1. 一台新交换机上架通电后，无需人工登录即可完成版本归一和基线配置加载，达到可远程网管状态。
2. 开局配置不是一次性脚本产物或手抄模板，而是可版本化、参数集中管理的渲染结果，不会出现逐台手配的漏项。
3. 业务配置是纳管之后的独立步骤，可反复重算下发，不需要重新开局。

## 二、核心设计范式

沿用 `prefix_list_management_design.md` 已确立的范式，不另造一套：

> **模板（带版本） + 设备绑定（期望状态） + 采集回读（实际状态） + 差异驱动部署**

对自动化上线而言，配置被拆成两段**分阶段**产出，而非一次性叠加成一份完整配置：

```
S2 开局下发 = 配置基线（厂商 × 角色，带版本）
            + 开局实例变量（SN、管理 IP、主机名、机房）

S4 业务下发 = 业务架构模板（组网形态：400G-BGP / 200G-BGP / 200G-OSPF …）
            + 业务实例变量（AS、Loopback、互联 P2P、端口映射、对端设备）
```

两段各自独立版本化：基线升级不影响业务架构模板，业务架构模板改版不需要重填开局变量，反之亦然。这也意味着一台设备同时持有两条独立的"期望状态 → 实际状态"链路，分别判定合规。

## 三、分阶段上线

自动化上线是多步骤过程，不是一次性把完整配置灌进设备。**开局阶段只下版本和基线配置，做到设备可网管即止**；业务配置（互联接口、路由协议、冗余机制）是设备纳管之后的独立步骤。

### 3.1 阶段划分

| 阶段 | 名称 | 配置内容 | 下发通道 | 完成标志 |
|------|------|---------|---------|---------|
| S1 | 登记与资源分配 | — | — | SN/机房/MDU/角色已登记，管理 IP、AS、Loopback 已分配 |
| S2 | 开局引导 | 软件版本 + 基线配置 | ZTP/POAP（带外） | 版本合规、管理 IP 可达、SSH/SNMP 可用 |
| S3 | 纳管确认 | — | — | 写入设备台账，进入可远程操作状态 |
| S4 | 业务配置 | 业务架构模板渲染结果 | SSH 下发（走变更工单） | 互联接口 up、路由邻居建立 |
| S5 | 上线校验 | — | — | 配置 diff 无偏差、业务巡检通过 |
| S6 | 移交运营 | — | — | 监控挂载、备份纳管、CMDB 入账 |

**S2 结束即"上线完成"的狭义定义**：设备已归一版本、可被系统远程操作。S4 之后才承载业务流量。两者可以隔天甚至隔周，取决于对端设备和线路进度。

### 3.2 为什么基线与业务必须分离

- **可达性依赖**：基线配置只需带外管理口（mgmt0 + 管理 VRF 默认路由）即可生效，不依赖任何上行业务链路。业务配置依赖互联对端也已就位，天然晚一步。
- **风险隔离**：基线配置短、全网同构、厂商差异小，适合塞进 startup-config 由 ZTP 一次性加载，错了重灌即可。业务配置长、形态多、易出错，适合在设备可远程登录后带 diff 预览和回滚下发。
- **可重入**：业务配置改版（如 200G OSPF 迁 BGP、新增 MDU 上行）只重跑 S4，不触碰开局链路。
- **职责归属**：S2 是机房交付动作，S4 是网络规划动作，拆开后两边可并行推进。

### 3.3 带外依赖与例外

基线配置走带外下发，前提是该 MDU 的带外交换机已在网，因此存在上线顺序约束：

```
oob 带外交换机 → 核心/汇聚 csw/pcs → 接入 rsw/asw
```

两类例外需单独处理：

- **oob 交换机自身上线**：带外网络尚不存在，只能走 console 服务器，或临时借带内上行引导。
- **新机房首台核心**：带外出口未打通，同上。

这两类不强求全自动，但基线配置仍由系统渲染产出，保证配置内容统一、可直接粘贴。

## 四、配置域与权威边界

配置分阶段下发，期望配置就不是"一整份 startup-config"，而是按**配置域**切分，每个域声明自己拥有哪些配置节。

| 配置域 | 拥有者 | 典型配置节 | 生命周期 |
|--------|--------|-----------|---------|
| 基线域 | 模块 2 配置基线 | AAA/TACACS、SNMP、NTP、syslog、SSH 与登录安全、mgmt 接口与管理 VRF、banner、本地用户 | **只在 S2 开局时生成下发一次**。之后设备配置由变更工单承接，不再与模板比对 |
| 业务域 | 模块 3 业务架构 | 互联三层接口、BGP/OSPF、BFD、M-LAG/peer-link、LACP、Loopback、路由策略 | S4 生成下发，可按需重算（改组网形态、加 MDU 上行时） |
| 其他 | — | 临时抓包口、一次性 ACL、现场排障残留 | 不在自动化范围内 |

**基线模板不做配置比对。** 设备在网运行后 running-config 会累积大量业务配置和现场改动，与"出厂开局该下什么"的模板差异巨大，比对产出的是噪音不是发现。配置历史留存由 `tasks/backup_device_config.py` + `tables/ConfigDB.py` 承接，配置变更由变更工单承接。

## 五、模块划分

| # | 模块 | 职责 | 作用阶段 |
|---|------|------|---------|
| 1 | **版本管理** | 软件镜像仓库、型号-目标版本矩阵、升级路径与前置校验、设备实际版本回读与合规判定 | S2 |
| 2 | **配置基线** | 网管类通用配置模板（AAA、SNMP、NTP、syslog、mgmt、登录安全）+ 三级变量，渲染出开局配置。纯生成，不比对 | S2 |
| 3 | **业务架构** | 组网形态模板：400G BGP、200G BGP、200G OSPF 等。端口角色、互联编址、路由协议参数、冗余机制（M-LAG/ECMP） | S4 |
| 4 | 开局引导（ZTP） | DHCP + 引导脚本 + 分发服务，多厂商适配。只负责交付版本与基线配置 | S2 |
| 5 | 上线校验 | 业务状态巡检：路由邻居、LACP/M-LAG、BFD、光模块、LLDP 对端核对，输出上线报告 | S3/S5 |

本轮按用户要求先细化 1、2、3；4、5 先占位，待前三者定型后再展开。

## 六、与现有系统的复用关系

| 需要的能力 | 现有实现 | 复用方式 |
|-----------|---------|---------|
| 配置解析/生成 | `lib_config/parsers`、`lib_config/encoders`（cisco/h3c/huawei） | 直接复用做 diff 与片段生成，按需补 Arista/锐捷 |
| 设备登录执行 | `lib_ssh/*Device.py` | 升级、回读、校验均走这里 |
| 配置备份与历史 | `tables/ConfigDB.py`、`tasks/backup_device_config.py` | 上线后纳入；期望配置另存，不混用 |
| 变更下发与审批 | `function_op/order_manage.py`、op_lists/op_devs | S4 业务配置下发、存量设备基线纠偏均走工单；S2 开局走 ZTP 不走工单 |
| 地址资源 | `function_collector/func_ipam.py`、`tables/IpamDB.py` | 互联 IP、管理 IP、业务网段申领 |
| 设备发现与台账 | `tasks/recon_device_inventory.py` | ⑤ 入网确认后触发 |
| 监控挂载 | `function_collector/func_zabbix.py`、skills `add/get-zabbix-host` | ⑧ 移交时调用 |
| POAP 原型 | `scripts/poap_cisco_nxos.py`（HTTP 拉 `<SN>.cfg`） | 模块 4 的起点，需补版本校验与状态回报 |

## 七、规范依据

模板内容必须与仓库既有规范一致，不在模板里另立标准：

- AS 号：`docs/network/AS号规划.md`（`42001` + DC 编号 + 层级编号）
- eBGP：`docs/network/bgp.md`（4 字节私有 AS、BFD 50/50×4、MD5、soft-reconfiguration、maximum-paths 32、仅宣告 Loopback0）
- OSPF：`docs/network/ospf.md`（存量机房）
- 命名：`docs/network/设备命名规范.md`（csw/pcs/rsw/asw/bbr/bbs/edr/esw/oob）
- 端口与 VLAN 描述：`docs/network/端口与VLAN描述规范.md`
- MDU 形态与规格：`docs/idc/MDU分类.md`、`docs/idc/MDU配置规格.md`

规范文档是模板的**唯一事实来源**；模板是规范的机器可执行表达。两者不一致时以规范为准并修模板。

## 八、分期实施

| 阶段 | 内容 | 产出 |
|------|------|------|
| P1 | 模块 1、2、3 设计定稿 + 数据库表结构 | 本目录设计文档 |
| P2 | 配置基线模板 + 变量 + 渲染引擎 | 页面能渲染出标准开局配置，供现场手工粘贴 |
| P3 | ZTP 引导链路（含版本交付） | 单台新设备跑完 S2，达到可网管 |
| P4 | 业务架构模板渲染 + S4 下发 | 一个 MDU 从空机柜到承载业务 |
| P5 | 上线校验报告 + 批量上线 | 整机房批量交付 |

P2 不依赖 ZTP 就有价值：开局配置由模板渲染产出，现场粘贴也比照着文档手抄可靠，漏项问题当场消除。模板正确性可以用现网设备的实际配置反向核对（人工比读，不做程序化 diff）。
